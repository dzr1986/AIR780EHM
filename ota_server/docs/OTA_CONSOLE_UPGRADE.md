# 管理台如何点升级

设备**不会开机自己拉包**。后台升级是 **推送 + 拉取**：你在管理台点「下发 OTA」→ 服务器发 MQTT **2004** → 模组 HTTP 来本服务下载 `.bin` → 写入后重启。

| 项 | 内容 |
|----|------|
| 管理台 | http://43.136.55.143/admin.html（Token 已预填，打开即登录） |
| 样机 IMEI | `862323084068124` |
| 固件名 | `PANSHI_CAT1_LuatOS-SoC_Air780EHM` |
| 文档日期 | 2026-08-18 |

打包产物见 [OTA_REAL_DEVICE.md](OTA_REAL_DEVICE.md)。菜单说明见 [OTA_ADMIN.md](OTA_ADMIN.md)。版本匹配见 [OTA_FOTA.md](OTA_FOTA.md)。

**闭环测试**页是模拟设备用的，不要拿来升真机。

---

## 1. 点击对应的链路

```text
你点「下发 OTA」
  → 服务器发 MQTT 2004（url + 目标版本）到 /panshi/device/{IMEI}/
  → 模组回 1004 ota_accepted
  → 模组 HTTP GET /api/site/firmware_upgrade?imei=...&version=当前版本
  → 有匹配包：200 + .bin；没有：≥300 / 404
  → 写 Flash，成功则 rtos.reboot()
```

包已经在服务器上，设备也不会自己来拿，必须再点一次「下发 OTA」（或串口 `AT+OTA`）。

开机、MQTT 连上之后，都**不会**静默检查升级。`FOTA_CFG.server_mode=self` 只决定触发之后打哪台服务器。

| 项 | 值 |
|----|----|
| IMEI | `862323084068124` |
| 当前版本 | `2044.001.019`（脚本 `001.000.019`） |

## 3. 上传包（每种目标版本做一次）

文件必须是**远程升级** `.bin`，例如：

`量产/SOC量产及远程升级文件/Air780EHM/PANSHI_CAT1_2044.001.020_LuatOS-SoC_Air780EHM.bin`

不要选 `.soc` / `.binpkg`（那是 USB 烧录包）。

1. 顶栏 **固件升级 ▾** → **我的固件**
2. **+ 创建固件**
3. **选择本地量产文件**，选上面的 `.bin`（文件名会自动填固件名、版本）
4. 核对：

| 栏 | 填什么 |
|----|--------|
| 固件名 | `PANSHI_CAT1_LuatOS-SoC_Air780EHM` |
| 版本号 version | **目标**，如 `2044.001.021` |
| 源版本 sourceVersion | **设备当前**，必须和模组现在的平台版一致。选 021 包时应填 `2044.001.020`，不要填成 `019` |
| core 版本 | `2044` |
| 允许升级 | 勾选 |
| 升级全部设备 | 样机测试不要勾 |
| 指定设备 IMEI | `862323084068124` |

5. **提交固件**

「我的固件」须看到：允许升级 = 是，且指定了该 IMEI（或已勾选升级全部）。

也可走 **固件升级 ▾** → **量产固件**，同样选 `.bin` 上传到当前项目。

---

## 4. 点升级（通知设备来拉）

1. 顶栏 **固件升级 ▾** → **下发升级**
2. **IMEI 列表**：`862323084068124`（多台用逗号分隔）
3. **目标版本**：与包的 version 一致，格式 `2044.001.xxx`（不要填 `001.000.xxx`）
4. 点 **下发 OTA**

下方黑框必须出现 JSON：

| JSON | 含义 |
|------|------|
| `"status": "PUBLISHED"` | MQTT 2004 已发出，设备会去拉包 |
| `"status": "SUCCESS"` 且 detail 含「无需再下发」 | 设备已经是该版本，按钮不会再发 MQTT |
| `"status": "FAILED"` 或「下发失败」 | 接口出错，看 error / detail |

黑框仍是占位文字、没有 JSON，才是页面没点到或脚本报错。

「批量升级落后设备」会按目标版本找出当前版本更低且未禁止的设备，一并下发。样机单测请用「下发 OTA」。

## 5. 看结果

| 去哪看 | 正常样子 |
|--------|----------|
| **我的任务** | 已下发 → 进行中。成功后可能仍停在进行中：模组成功后立刻重启，1004 `success` 经常发不出来 |
| **调试日志** | 该 IMEI 决策为「下发差分包」/ `UPGRADE` |
| **我的设备** | 一两分钟后刷新，当前版本应变高 |

设备必须在线（能回 1003 / 1008）。关机、没网、或列表里是「禁止」，点了也不会升。

被循环保护禁了：到 **我的设备** 改回 **允许**（会清零连续下发计数），再下发。

最终以设备重启后的版本为准（MQTT **2008** 查 **1008** 的 `firmwareVersion` / `scriptVersion`）。

---

## 6. 下发内容（后台发出的 2004）

```json
{
  "dataType": "2004",
  "action": "ota",
  "url": "http://43.136.55.143/api/site/firmware_upgrade?",
  "version": "2044.001.020",
  "timeout": 300000,
  "full_url": 0,
  "messageId": "ota-srv-xxxxxxxx"
}
```

`url` 以 `?` 结尾。模组自动拼 `imei`、`firmware_name`、`version`（**当前**平台版本）、`project_key`。2004 里的 `version` 只给任务台账用，拉包匹配看设备上报的当前版本。

- [ ] 确认设备在线，且「我的设备」为允许升级

- [ ] 已上传远程升级 `.bin`（不是 `.soc` / `.binpkg`）
- [ ] 固件名 = `PANSHI_CAT1_LuatOS-SoC_Air780EHM`
- [ ] version = 目标（如 `2044.001.020`），sourceVersion = 设备当前
- [ ] 指定 IMEI = `862323084068124`（样机测试不要勾「升级全部」）
- [ ] 「下发升级」目标版本填 `2044.001.xxx`，点「下发 OTA」
- [ ] JSON 出现 `"status": "PUBLISHED"`
- [ ] 调试日志出现 UPGRADE；重启后 1008 版本变高
- [ ] 不要用「闭环测试」页升真机
